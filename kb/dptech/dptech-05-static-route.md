# 迪普 · 静态路由

> ⚠️ 迪普公开资料有限，以下命令整理自公开实践资料，与华为/思科风格部分相似但不完全相同，所有配置请以实际型号的官方手册或迪普售后确认为准。

## 命令速查

| 功能 | 命令 | 视图 | 说明 |
|---|---|---|---|
| 配置静态路由 | `ip route-static 192.168.30.0 24 192.168.20.67` | 配置模式 `[DPTECH]` | 目的网段 + 前缀长度 + 下一跳，前缀长度直接写数字 |
| 配置默认路由 | `ip route-static 0.0.0.0 0 10.0.0.2` | 配置模式 `[DPTECH]` | `0.0.0.0 0` 表示缺省路由 |
| 配置黑洞路由 | `ip route-static 192.168.1.0 255.255.255.0 null 0` | 配置模式 `[DPTECH]` | 出接口指向 null 0，流量被丢弃，常用于防环（也见点分掩码写法） |
| 简写默认路由 | `ip route 0.0.0.0/0 <下一跳>` | 配置模式 `[DPTECH]` | 与 `ip route-static` 两种写法并存，适用版本以官方手册/售后确认为准 |
| 配置 IPv6 默认路由 | `ipv6 route ::/0 <下一跳> [出接口]` | 配置模式 `[DPTECH]` | 可选携带出接口 |
| 配置 IPv6 静态路由 | `ipv6 route <目的前缀/长度> <下一跳>` | 配置模式 `[DPTECH]` | 按 `::/0` 同语法类推（以官方手册/售后确认为准） |
| 查看路由表 | `show ip routing-table` | 用户/配置视图 | 核对静态路由是否生效、下一跳是否可达 |

## 典型示例

```
<DPTECH> conf-mode
[DPTECH] ip route-static 192.168.30.0 24 192.168.20.67
[DPTECH] ip route-static 0.0.0.0 0 10.0.0.2
[DPTECH] ip route-static 192.168.1.0 255.255.255.0 null 0
[DPTECH] ipv6 route ::/0 <下一跳>
```

## 陷阱与差异

- 前缀长度直接跟在网段后（`192.168.30.0 24`），华为用点分掩码、思科在部分场景用反掩码，写法互不通用。
- 黑洞路由把出接口指向 `null 0`，类似思科的 `Null0`，常见于汇总防环或压制异常网段流量；同一命令里也出现了点分掩码（255.255.255.0）写法，说明掩码风格按版本混用。
- `ip route-static` 与 `ip route 0.0.0.0/0` 两种写法在公开资料中并存，⚠️ 同一设备混用前先确认当前版本支持的写法（以官方手册/售后确认为准）。
- 静态路由优先级/浮动路由参数未在公开素材中出现，需要时以官方手册为准。
- 路由的取消命令（`no`/`undo` 形式）未核实，删除前先查手册确认语法。

## 高危操作 ⚠️

- 默认路由指向错误下一跳会把全网流量引入黑洞，⚠️ 配置后立即用 `show ip routing-table` 与连通性测试验证。
- 黑洞路由配置错误（网段写错）会直接丢弃正常业务流量，⚠️ 下发前逐字符核对网段与掩码。
- 远程改配路由时，⚠️ 先确认存在不依赖本次变更的管理路径，防止自锁失联。
